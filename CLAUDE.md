# CLAUDE.md

Design tool for previewing lenticular security threads on banknotes (Oberthur Fiduciaire x ArtCenter studio). See README.md for what it does and the code layout.

## Commands

- `npm run dev`: dev server. From the parent folder, the `thread-playground` launch config runs it on port 5174.
- `npm run build`: type-check (TypeScript 7) and build. Run it before every commit.
- `npm run lint`: Oxlint. `src/components/ui/**` (generated shadcn code) is ignored.

## Working with Keller

- **Branches:** the app has live users, and main deploys to them through Vercel. Do all work on the `dev` branch, or a feature branch off it, and commit and push there. Merge into main or push main only when Keller explicitly says to in that conversation. The Supabase backend is shared by every branch, so treat database, function or template changes as live too, and check with Keller first.
- Plan first. Don't write code until Keller says to build. A scope change or "let's focus on X" means update the plan, not implement it.
- He iterates by giving feedback on the running app. Commit after each round, with a message that says what changed.
- Call notes "banknotes" in the UI.
- No tutorial or hint text in the UI. Keep only what's needed, and name terse field labels in a `title` tooltip instead. Where a control is hard to grasp the first time (1 → 5, Cycle), use `Explain` (`src/editor/LensVisuals.tsx`): a hover tooltip with a small picture and one line.

## UI rules

- Use shadcn components for every control (`npx shadcn@latest add <name>`, base-nova style, Base UI primitives). Don't hand-roll buttons, inputs, menus or dialogs. Compose them in `src/components/controls.tsx`. Keller will restyle `src/components/ui` and the tokens in `src/index.css` later.
- After adding a component, replace `from "cn"` with `from "@/lib/utils"` in the generated files.
- Number fields are Figma-style `ScrubField`s (drag the label to scrub), not sliders.
- New UI copies what is already there rather than inventing sizes: match the nearest existing row, field, button or editor (text size, height, padding, radius, selected and hover colours). The palette is neutral; the few accent colours already mean something: sky = ↕, amber = ↔, fuchsia = editing on the canvas (windows, watermark box), rose = snap guides. Keller noticed when the watermark's first pass drifted from this.
- Project list: a top bar with the app name, save status and an account menu (username, Sign out); a Projects heading with a New project button that opens a name dialog; a Demo button next to it. Sign-in is a single username field with Continue.
- Editor layout: full-screen canvas with floating panels.
  - **Top left:** back to Projects, the project name, and the collapsible Banknotes list. Each banknote opens to its layers, Security thread and Watermark (once added from the + on the banknote's row); the selected banknote opens by itself, the chevron opens or closes any. A banknote's row selects the banknote itself, a layer row that layer. Layer rows are built like the banknote rows (same text size, height and highlight), indented so the icon sits under the banknote's thumbnail and the highlight starts there, not at the list's edge.
  - **Bottom:** play/pause, with Record movement, the # frame-number toggle and Playback settings as small icon buttons stacked beside it, always. That block is exactly as wide as the tilt pad's panel above it (`TILT_PANEL_PX`), so with nothing selected the whole bar is. Cycle lives only in the right panel's lens effect. A selected banknote's frames appear as clips on a track to its right.
  - **Bottom left:** the tilt pad, just above the playback bar (the Banknotes list stops short of it), a square you drag in any direction to tilt every banknote (vertical = up/down, horizontal = side; it holds where you let go), with the ↕ and ↔ angles as one row of small `ScrubField`s under it, each holding its axis's lock (shown on hover, and always while locked; locks also apply to canvas drag and spring-back), and a back-to-flat button in the pad's top-right corner that only appears once you've tilted (or while playing). The lamp (Hold up to the light, a `Toggle` pressed in `primary` like the timeline's) sits in the top-left corner. Both directions are always available, whatever the lens.
  - **Right:** properties, only while a banknote is selected: its name and Export, then a tab per part, Banknote, Thread and Watermark (once added), mirroring the layers in the list (Keller chose this over a Figma-style Design | Lens split). The open tab is the part picked: a click on the canvas or in the list turns to it, and turning to a tab picks that part (Watermark places it, as its row does), so the panel never grows with features. The tabs carry no group titles of their own. Banknote: size, background. Thread: placement with the Windows card, Artwork, and Lens effect (⋯ for 1 → 5 on its title; Edit thread, a primary button, first, then the lens's basic controls and its preview as in the thread editor (`EffectSection`), or with Mixed angles the whole print; then Offset with Shuffle when it matters). Watermark: its image with the Invert switch, Auto levels and the levels slider, then X, Y, W, Depth; Remove watermark sits at the right of the tabs while its tab is open. While Keller compares ways to switch parts (3 November), a temporary Try switch at the panel's foot (`src/lib/panelOption.ts`, per browser) shows them as tabs, as folder tags down the panel's left edge (the open one joined to the panel, the open part named under the banknote), or as a tree (the banknote's row over its indented parts, built like the list's rows). All three are the same `Tabs` underneath, vertical for tags and tree. Keep the one he picks and remove the others and the switch. Floating panels stay a little see-through (`Panel`, 95% with a blur), as Keller wants; fields (`ScrubField`) have a solid fill instead, since a banknote behind tints the panel and a see-through fill all but vanished. A click picks exactly what it lands on, and nothing is remembered (Keller, 3 November): the banknote (on the canvas away from its thread and watermark, its label, or its row) shows Banknote, its thread or watermark (on the canvas or its layer row) that layer, and another banknote, a new one or a copy shows that banknote itself, never the layer picked before. Only a drag that tilts the selected banknote keeps its layer showing. Removing the watermark it shows leaves the banknote selected. The canvas outlines only what is picked, firmly, and what a click would pick under the pointer, lightly (Keller asked for hover on the whole thread, not only windows): the banknote with its offset outline (2 px picked, 1 px hovered, `primary/25`), its thread or watermark with a `primary` ring edged in the background colour (2 px, 1 px), drawn in NoteView so it follows the tilt, never exported. The picked outlines step back while playing or dragging, and window editing and watermark placing keep their fuchsia editors instead. New effects (Intaglio…) become new layers, siblings of the thread. Panels are top-level `Group`s holding nested `Section`s split by thin inset dividers, with few titles. Windows is a compact card (switch, strip showing where windows sit, selected window's Start/End, full list on expand). Not collapsible for now.
  - **Thread editor** (`src/editor/ThreadEditor.tsx`): opened by Edit thread (in the panel's Lens effect, or the button that hangs just under a picked thread on the canvas, under the banknote for a vertical one) or a double-click on a thread (any of them picks the banknote's Security thread layer, so the panel shows it on the way back), full screen over the canvas (not a dialog, so ⌘Z still works; the canvas stays mounted underneath because it runs playback). Middle: `PatternView`, the thread in its own direction over two or three repeats (three only while the thread stays at least 140 px wide), real artwork at the current tilt, dashed repeat ends, outlines, optional ridge hatching; draw, move and resize there. Right, one scrolling list (Keller's Figma-style tabs were meant for the canvas panel, not here): the selected section's Area (mm on the title, not in each field) and Frames (tinted with the frame colours), then the Lens controls (`EffectSection` with `preview={false}`, the section's own with Mixed angles, else the banknote's marked Shared), then Thread: direction, T and Artwork (`ThreadSettings`). Empty thread shows as checkerboard: drag there to draw a section, double-click to fill that gap, or use Fill on the No gaps check to fill every gap (`fillGaps` in `src/lib/pattern.ts`: a section sharing a whole side with a gap grows over it, so a lane cut short runs on again; one undo step). Every new section placed in empty thread, drawn, added or filled, goes through `placeSection`: it copies the lens and track of the section it sits in line with, else the one it borders most, and is named after it ("Lane ↔ 2"); only one touching no section is plain (the banknote's lens, every frame, "Section N"). - `exportRender.ts` redraws NoteView on a canvas for MP4/GIF export. When you change how NoteView draws a banknote, change the export renderer to match.

## Product decisions

- It's a general tool, not tied to the Flight notes: a project is created with just a name, and banknotes can be any size. There are no built-in denomination presets.
- **Frames:** 2 to 5 per banknote. Lenticular optics are not simulated: frames are artwork shown in turn as you tilt.
- **Tilt:** flat sits at the middle of the middle frame by default (frame 3 of 5, frame 2 of 4), so one tilt direction plays on towards the last frame and the other back towards frame 1. Flat is set with the pin on the frame strip in the thread editor's Lens (`FlatStrip`), snapping to half-frame steps (`tilt.flatAt` as a number; 'start' from older saves = 0); the timeline shows it read-only. Hidden frames are always the ones farthest from flat, so moving flat moves them. "1 → 5" sets whether frames run top to bottom (default for new projects; older projects stay bottom to top) or bottom to top, and left to right (default) or right to left. Both live in the ⋯ menu on the thread editor's Lens title (`LensMenu`), since they rarely change. Tilt goes to ±90° (`TILT_LIMIT`, edge-on), not a setting: it limits manual tilt and playback (`SWEEP_MAX`) and decides hidden frames. Light and shade on the banknote still scale to full at 60° (`SHADE_DEG`). `tilt.viewDeg` from older saves is ignored. Playback is a project-wide list of moves played in order and looped (`src/lib/moves.ts`, edited in the Playback popover): preset moves (↕ Up/down, ↔ Side to side, Diagonal, Circle) go out from flat and back (up/down and side can start from any angle instead, e.g. swing −12° ↔ +12° without returning to flat; every move starts from flat and returns to flat before the next), by default through one full Cycle on each tilt they use; a recording (Record movement, then drag on the tilt pad) is saved to the project's Recordings and becomes the whole playlist on its own; it plays in its own time joined to flat. The Playback settings popover has one plain list of moves on the left (presets, then recordings; click to add to the playlist, recordings can be deleted), the Playlist on the right (reorder, remove, per-move ↕/↔ reach), and Motion (speed, hold, curve, fade) under it. The pad draws the path. Live playback and export read the same plan. Projects without a list play what the old Tilt setting chose. The timeline starts at 0° too. Tilting must read as up vs down (and left vs right), using a strong per-note perspective.
- **Lens effects:** one lens per banknote (`src/lib/lens.ts`), or one per thread section with Mixed angles: the effect, Cycle, flat, band, wobble and 1 → 5 directions are edited for the selected banknote (or section) only (a new banknote starts from the last one's); playback and the tilt pad follow the selected banknote, or the first. Presets Up/down, Side to side, Both ways, Reveal on one tilt, Custom (by tilt or by lens), named by their ridges: Horizontal (plays on up/down), Vertical (side to side), Diagonal 45° (same cycle on both tilts), Partial reveal on one tilt (one tilt plays every frame, the other never shows the outer ones at any tilt up to 90° (`HIDE_LIMIT`), even with the hand drifting `Wobble` degrees (default 5°) onto the fast tilt: the slow cycle is computed and the hidden count follows from it, never typed: the strip shows the slow tilt's reach as a band whose ends you drag to hide more or fewer frames (`revealLevel`, a step inwards from the widest); if the fast cycle is too short for the wobble, the panel shows the minimum fast cycle in red. This is for real banknotes, not just the prototype), Custom angle (by tilt or by lens). The dropdown shows a ridge picture and one line per option. Each tilt has its own cycle; the lens angle follows from them. The presets all store their one Cycle in `cycleDeg` (Partial reveal's slow cycle is computed); only Custom reads `cycleXDeg`. Switching effect (`src/lib/switchEffect.ts`) keeps flat, band, wobble and directions, carries the fastest playing cycle into a preset (back to the default if it's over 180°), and starts Custom from exactly what the current effect gives. No preset numbers. Hidden frames are an outcome shown with an eye-off icon and ↕/↔, never a setting. Lenticular only, no microlens arrays. The Lens effect's tilt map is only a picture (it doesn't tilt banknotes): a click swaps it for the print and back (no toggle; the hover tooltip says so). The print (`src/lib/print.ts`, `src/editor/PrintView.tsx`) is the selected banknote's thread, magnified, with its real frames tiled as on the banknote and cut into strips under the ridges: strips at the ridge angle, each frame's strip as wide as its length, the frame seen flat under each ridge's middle, drawn the same way round as the tilt map. The strips seen at the current tilt stay lit. Cycle alone never changes it. Ridges (shown only with the print) sets how many ridges it draws across the thread; it and the view are remembered per browser (`src/lib/printView.ts`), not saved in projects. Only the lens lab's ridge maths came over, none of its pitch numbers or print checks.
- **Thread pattern** (`src/lib/pattern.ts`, `ThreadPattern` on `Note.pattern`): frames are full-thread artwork and sections are masks over them. Sections sit in one repeat (1 to 250 mm, 4 by default) that tiles the thread; along is mm from the repeat's start, across a share of the thread's width. Editing snaps to 0.5 mm along and twelfths across, and sections never overlap: drawing cuts back, moving slides until blocked, and edges on one seam move together. Mixed angles is off by default: off, every section plays the banknote's lens (a section keeps its own for when it's switched back on); on, each plays its own, and fields it leaves out take the defaults, never the banknote's. Every section's print has one strip per banknote frame at that frame's length, so flat and the cycle mean the same everywhere; a section's track picks the frame each strip shows (by frame id, a shorter story padded). A banknote without a pattern is one section over the whole thread and is drawn by exactly the old path (tested against the old renderer). Presets: Single lens, Split band, Alternating (segments), Chevron lock; they keep the banknote's flat, Cycle and directions. The rules (`src/lib/patternRules.ts`) only ever warn: every window shows each tilt wherever the print lands, one rest frame, frames only some sections show under ridges within 10° of their tilt's axis (mirrored pairs fine), one strip count (only strips set for another number of frames, as after adding or deleting one; a story that repeats frames is fine), minimum 1 mm by 1 mm less a 0.2 mm dead zone where angles meet, at most 3 ridge angles, no gaps. The sizes are placeholders until Oberthur confirms them. The print isn't registered to the banknote: the offset is a preview only (`src/lib/patternOffset.ts`), remembered per browser by banknote, never saved or undone, shown only when some section is shorter than the repeat, followed by the canvas and export; the thread editor shows the repeat from its start. With Mixed angles, playback sweeps each tilt at its fastest section's cycle (both tilts when both play and there are no moves), and the timeline follows the section selected in the thread editor, else the first. The print cuts each section at its own ridge angle with one ridge width, over two repeats where it can (at most three thread widths long); gaps print nothing.
- **Timeline:** each frame has a relative `length`, and its share of the total is its share of the cycle. Cycle (`tilt.cycleDeg`) is per banknote, with the lens. `tilt.transition` (Fade), speed, curve, hold at ends and the moves list are project-wide. Fade and motion controls live in the Playback settings popover; the default is 1× speed, Smooth curve, no hold. They are stored on each note but always edited for all notes together, and must never resize the timeline. Past one cycle the frames loop. The timeline shows one cycle with no angle ruler.
- **Images:** they always stay upright, even on horizontal threads. Complete images fill the thread thickness at their own aspect ratio and repeat to the banknote edge. Image gap sets optional spacing between copies (0 mm by default); it is separate from the paper bridges between windows.
- **Watermark:** at most one per banknote, a sibling of the thread (`note.watermark`, `src/lib/watermark.ts`), added from the + on the banknote's row; Duplicate keeps it. One image, read only by brightness, since a watermark is paper thickness and has no colour, and it only ever gets lighter, since it is light coming through thinner paper (Keller's rules). By default the image's light parts are the thinner paper (on transparency, as far as they are light; on an opaque background, as far as they are lighter than it), so it glows where the image is light, as a photo of a watermark held to the light does; Invert (a switch under Replace, any image; `watermark.invert`, saved only when on) makes the dark parts thinner instead, so a black logo glows. Keller chose this way round on 2 November (the first lighter-only build had them the other way). The background (its edge pixels, or transparency) and whatever lies the other side of it stay plain paper (`thinness` in `src/lib/relief.ts`). Levels then shape how thin that reading makes the paper (Keller asked on 2 November to control how an imported image comes out; built 3 November), three handles as in Photoshop's Levels on the slider under Auto levels: where the watermark starts (black; anything fainter stays plain paper), midtones (grey, a gamma that keeps its place between the ends as they move) and where it reaches the thinnest (white); plain paper always stays plain (`levelsCurve`). Auto, the default (no `watermark.levels`), fits them to each image as it is read (`autoLevels`): the start just above the background's speckle (4× the spread of its edge pixels, so JPEG noise stays plain paper; 0 on transparency) and the thinnest where all but 0.5% of the image reaches, so a faint scan comes up, gamma 1. Moving a handle saves `watermark.levels` and turns Auto off; switching Auto levels off keeps Auto's levels to set by hand, on again drops them. A new image, or removing it, starts on Auto again. On a black-on-white JPEG left the default way round, its compression ringing can still show faintly round the logo; Invert, which is the right reading for it, comes out clean. It is drawn as one layer colour-dodged over the design and under the thread, up to `THINNEST_GAIN` (2×) the light for the thinnest (`lightPixels`): it brightens the design in proportion, so it shows in the banknote's own colours, plain paper is unchanged and dark print stays dark, as ink blocks light. Its opacity is how much of that light comes through, so the reveal is more light, not an image fading in. On very light paper the screen has little room above the paper colour, so detail inside the glow can merge into white; only dimming the banknote when lit would fix that, which Keller ruled out. Darker, thicker parts (multiply), Hard light, Blend modes and an SVG Fill colour were all tried and removed: paper can't be coloured, and darkening reads as print. The thumbnail beside Replace shows the image in greyscale. Placed by its top-left corner in mm, its height following the image; Depth (0 to 100%) sets how strongly it shows at its clearest. On the canvas it handles like the thread, as Keller asked: a press on it, faint or clear, picks it and a drag moves it (0.5 mm steps, once past 3 px so a click doesn't nudge it), so dragging there moves the watermark instead of tilting the banknote; with Depth 0, or in thumbnails, it takes no press. Placing works like windows, with no mode: picking the Watermark layer, pressing the watermark on the canvas, adding it or uploading its image shows the banknote flat with the watermark clear and its box to drag (styled like the window editor: solid fuchsia border with a ring; corners resize with the proportions kept, 0.5 mm steps, arrow keys nudge); a click elsewhere on the banknote, the empty canvas, Escape or another layer ends it, and Delete removes the watermark. Placing pauses playback and hides the tilt pad. Reliefs are worked out in steps (`src/lib/relief.ts`) so a drag on the levels stays live: each image's pixels once (at most 1024 px), then a reading per Invert (its thinness and Auto's levels, the last one showing while the next is worked out), then a light layer per levels drawn through a 256-entry table (`lightPixels`), a few of each kept. NoteView draws that layer on a canvas at the size it shows at (`reliefPixels`), scaled down smoothly so fine detail doesn't turn to grain, and export draws the same layer the same way.
- **Light:** how clearly the watermark shows (`src/lib/light.ts`). Flat in reflected light it is faint (`WATERMARK_FAINT` of its depth); tilting either way brings it out, clearest from `WATERMARK_CLEAR_DEG` (30°) on; held to the light it is clear at any tilt. Nothing else changes in the light: Keller was explicit that the design and the thread must look the same (no grey or monochrome filter, no dark thread, no darkened canvas). The lamp on the tilt pad, or a tap of L, holds every banknote up to the light until switched off; holding L peeks at the other light while it is down. The light fades in and out over `LIGHT_RAMP_SECONDS`. The live light is preview state (`useTilt`), not saved. Playback has a ☀ Hold to light move: flat, the light fades in, holds for its seconds and fades out; recordings keep the light too, and the pad draws the stretches played up to the light bold (a ring round flat for Hold to light). No amber anywhere for light: the app uses amber for ↔ and sky for ↕. Export matches the canvas: the watermark follows each frame's tilt and light, and the lamp left on makes it clear for the whole video.
- **Threads:** they can run vertically or horizontally, with windows switched on or off (off = continuous). Windows are individual start/end sections, listed in the panel and edited directly on the canvas, with no edit mode: selecting a window (panel row, canvas, switching windows on, or +) starts editing, and clicking elsewhere on the banknote, the empty canvas or Escape ends it: draw, move, resize, or delete, snapping to 0.5 mm. Start/End fields provide precise adjustment. Editing pauses playback and shows the banknote flat with hidden artwork faintly visible. On the canvas, dragging a thread moves it across the banknote (X for vertical, Y for horizontal, 0.5 mm steps), and clicking a window selects it for editing. Legacy repeating patterns migrate to sections. There is no white surround.

## Data

- Everything is stored in the browser's IndexedDB (`src/lib/db.ts`), images as blobs, and nothing goes to a server. Projects therefore live in the browser they were made in. Use the Demo button on the project list to get sample content anywhere.
- When you change a saved shape, add a migration in `migrateProject` (`src/lib/notes.ts`) so existing projects keep working. An open tab can still hold the old shape in memory until it reloads.
- Image hooks that read a module-level cache (`useImageUrl`, `useRelief`, NoteView's `useImageAspect`) work out the value while rendering and, when it was missing, re-check in their effect: another view can fill the cache between this one's render and its effect, and the React Compiler won't recompute it without a state change.
- Every image a banknote uses must be listed by `projectImageIds` (`src/cloud/repository.ts`), or it isn't uploaded on save or copied from the demo, and by `noteImageIds` and `copyNote` (`src/lib/store.ts`), so Duplicate gives the copy its own. A new image field goes in all three.

## Testing in the built-in browser pane

- The pane throttles rendering while hidden, so DOM checks from JavaScript can look stale. Take a screenshot to force a render.
- Synthetic pointer events need `pointerId: 1`, or `setPointerCapture` throws.
- Test with a throwaway project and delete it afterwards. Don't edit Keller's own projects.
