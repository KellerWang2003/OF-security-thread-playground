# CLAUDE.md

Design tool for previewing lenticular security threads on banknotes (Oberthur Fiduciaire x ArtCenter studio). See README.md for what it does and the code layout.

## Commands

- `npm run dev`: dev server. From the parent folder, the `thread-playground` launch config runs it on port 5174.
- `npm run build`: type-check (TypeScript 7) and build. Run it before every commit.
- `npm run lint`: Oxlint. `src/components/ui/**` (generated shadcn code) is ignored.

## Working with Keller

- **Branches:** the app has live users, and main deploys to them through Vercel. Do all work on the `dev` branch, or a feature branch off it, and commit and push there. Merge into main or push main only when Keller explicitly says to in that conversation. The Supabase backend is shared by every branch, so treat database, function or template changes as live too, and check with Keller first.
- Plan first. Don't write code until Keller says to build. A scope change or "let's focus on X" means update the plan, not implement it.
- He iterates by giving feedback on the running app. Commit after each round, with a message that says what changed.
- Call notes "banknotes" in the UI.
- No tutorial or hint text in the UI. Keep only what's needed, and name terse field labels in a `title` tooltip instead. Where a control is hard to grasp the first time (1 → 5, Cycle), use `Explain` (`src/editor/LensVisuals.tsx`): a hover tooltip with a small picture and one line.

## UI rules

- Use shadcn components for every control (`npx shadcn@latest add <name>`, base-nova style, Base UI primitives). Don't hand-roll buttons, inputs, menus or dialogs. Compose them in `src/components/controls.tsx`. Keller will restyle `src/components/ui` and the tokens in `src/index.css` later.
- After adding a component, replace `from "cn"` with `from "@/lib/utils"` in the generated files.
- Number fields are Figma-style `ScrubField`s (drag the label to scrub), not sliders.
- Lengths are always mm in the code and in saves; only how they read changes (see Units below). A length field is a `LengthField` (`LengthNumberField` in a dialog), which takes and gives mm and carries the unit menu on its unit; a length in text goes through `formatLength` or `lengthIn` with the unit from `useLengthUnit` (`src/lib/units.ts`). Never write "mm" after a length by hand.
- **Visual hierarchy** (Keller asked for one set on 3 November; follow it everywhere):
  - Type, five steps in the panels: 14px (`text-sm`) for content: list rows, values in fields, inputs, menus. 13px (`text-[13px]`) for panel headings: the right panel's part tabs and `Group` titles. 12px (`text-xs`) for labels: field labels, counts. 11px (`text-[11px]`) for the small label over each control in a side panel (`Labeled`, regular weight, always shown, as Figma's property labels: Keller wants no one guessing what T or a strip means; leave it off only where a word in or beside the control already says it) and for small headings: `Section` titles, Banknotes · n, Presets, Sections · n, the export dialog's, in sentence case. 10px (`text-[10px]`) for notes on chips and in pictures (frame numbers on clips, durations); pictures may go smaller. Only the project list and sign-in pages go larger.
  - Weight: 400 for values and body, 500 for anything interactive (buttons, tabs, rows) and small headings, 600 for headings (`Group` titles, the open tab).
  - Buttons: primary (filled, the default variant) is the one main action of a panel or section: Export (in the corner bar, top right), Edit in Thread Studio under a picked thread, a dialog's confirm, New project, Continue. Secondary (`outline`) is a standalone action beside a primary or where a filled one would shout: Cancel, Replace or Upload an image, Import, presets and strips in the thread editor. Ghost (`ghost`, `IconButton`) is for toolbars and inline actions: add, duplicate, delete, undo, zoom, menus, rows. Destructive only confirms a delete in a dialog.
  - Dividers, two levels (Keller): dark, full width (`border-border`, as the `Separator` under the project name) under a panel's header and between groups or other big sections; lighter and inset with padding (`border-border/70`, a `Group`'s own `divide-y`) between the sections inside one. Panel outlines stay `border-border/70`.
  - Corners (Keller asked for one radius on 3 November): every floating panel has the same corners, 15 px (`--radius` + 6 px + the 1 px border, so `rounded-lg` controls inset 6 px sit concentric inside), set once on `Panel`; don't give a panel its own rounding. That covers the Banknotes panel, the corner bar, the right panel, the tilt pad, the playback bar, and Thread Studio's top bar, panels and zoom bar, which copies the canvas's corner bar. Controls inside keep `rounded-lg` or smaller, and small labels on a drawing (Thread Studio's measures) keep their own.
  - The right panel's part tabs carry their list icons and scroll sideways once they don't fit (`TabStrip`: an edge fades while more lie beyond it, and the open tab scrolls into sight). There is no zoom percentage anywhere: nothing says what 100% is (Keller).
- New UI copies what is already there rather than inventing sizes: match the nearest existing row, field, button or editor (text size, height, padding, radius, selected and hover colours). The palette is neutral; the few accent colours already mean something: sky = ↕, amber = ↔, fuchsia = editing on the canvas (windows, watermark box), rose = snap guides. Keller noticed when the watermark's first pass drifted from this.
- Project list: a top bar with the app name, save status and an account menu (username, Sign out); a Projects heading with a New project button that opens a name dialog; a Demo button next to it. Sign-in is a single username field with Continue.

## Product decisions

- It's a general tool, not tied to the Flight notes: a project is created with just a name, and banknotes can be any size. There are no built-in denomination presets.
- **Units** (`src/lib/units.ts`): Keller asked for units beyond metric (3 November). mm, cm, in and pt, mm the default for everyone (no locale guessing); px is left out, since it has no physical size without a ppi. One pick for the whole app, made from the menu on the unit of any length field (the right panel, New banknote), remembered per browser like the panel width, never saved in a project or undone, so switching never changes a value. Each unit reads to its own decimals (mm 0.01, cm and in 0.001, pt 0.1), and the banknote labels on the canvas, the window list, screen-reader labels and the Checks follow it. Typed values are kept exactly (to a millionth of a mm), and a unit typed after the number (6.14in, 6.14", 15.6cm, 442pt) converts without switching. Scrubbing and the arrow keys (Shift for ten steps) step the largest round number (1, 2 or 5 of a power of ten) of the unit that isn't coarser than the field's mm step: 0.5 mm steps 0.05 cm, 0.01 in or 1 pt, Offset's 0.1 mm 0.01 cm, 0.002 in or 0.2 pt. Canvas and Thread Studio drags keep their mm grid in every unit (0.5 mm, a frame's image 0.1 mm; gaps fill cell by cell on it), so a dragged window can read 0.512 in. Limits stay in mm, and the number shown at a limit can be typed (a banknote's 20 to 250 mm reads 0.787 to 9.843 in). Thread Studio's fields are `LengthField`s too: R and T beside the thread, and the picked frame image's X, Y and W (0.1 mm steps: 0.01 cm, 0.002 in or 0.2 pt).
- **Frames:** 2 to 5 per banknote. Lenticular optics are not simulated: frames are artwork shown in turn as you tilt.
- **Tilt:** flat sits at the middle of the middle frame by default (frame 3 of 5, frame 2 of 4), so one tilt direction plays on towards the last frame and the other back towards frame 1. Flat is set with the pin on the frame strip in the thread editor's Lens (`FlatStrip`), snapping to half-frame steps (`tilt.flatAt` as a number; 'start' from older saves = 0); the timeline shows it read-only. Hidden frames are always the ones farthest from flat, so moving flat moves them. "1 → 5" sets whether frames run top to bottom (default for new projects; older projects stay bottom to top) or bottom to top, and left to right (default) or right to left. Both live in the ⋯ menu on the thread editor's Lens title (`LensMenu`), since they rarely change. Tilt goes to ±90° (`TILT_LIMIT`, edge-on), not a setting: it limits manual tilt and playback (`SWEEP_MAX`) and decides hidden frames. Light and shade on the banknote still scale to full at 60° (`SHADE_DEG`). `tilt.viewDeg` from older saves is ignored. Playback is a project-wide list of moves played in order and looped (`src/lib/moves.ts`, edited in the Playback popover): preset moves (↕ Up/down, ↔ Side to side, Diagonal, Circle) go out from flat and back (up/down and side can start from any angle instead, e.g. swing −12° ↔ +12° without returning to flat; every move starts from flat and returns to flat before the next), by default through one full Cycle on each tilt they use; a recording (Record movement, then drag on the tilt pad) is saved to the project's Recordings and becomes the whole playlist on its own; it plays in its own time joined to flat. The Playback settings popover has one plain list of moves on the left (presets, then recordings; click to add to the playlist, recordings can be deleted), the Playlist on the right (reorder, remove, per-move ↕/↔ reach), and Motion (speed, hold, curve, fade) under it. The pad draws the path. Live playback and export read the same plan. Projects without a list play what the old Tilt setting chose. The timeline starts at 0° too. Tilting must read as up vs down (and left vs right), using a strong per-note perspective.
- **Lens effects:** one lens per banknote (`src/lib/lens.ts`), or one per thread section with Mixed angles: the effect, Cycle, flat, band, wobble and 1 → 5 directions are edited for the selected banknote (or section) only (a new banknote starts from the last one's); playback and the tilt pad follow the selected banknote, or the first. Presets Up/down, Side to side, Both ways, Reveal on one tilt, Custom (by tilt or by lens), named by their ridges: Horizontal (plays on up/down), Vertical (side to side), Diagonal 45° (same cycle on both tilts), Partial reveal on one tilt (one tilt plays every frame, the other never shows the outer ones at any tilt up to 90° (`HIDE_LIMIT`), even with the hand drifting `Wobble` degrees (default 5°) onto the fast tilt: the slow cycle is computed and the hidden count follows from it, never typed: the strip shows the slow tilt's reach as a band whose ends you drag to hide more or fewer frames (`revealLevel`, a step inwards from the widest); if the fast cycle is too short for the wobble, the panel shows the minimum fast cycle in red. This is for real banknotes, not just the prototype), Custom angle (by tilt or by lens). The dropdown shows a ridge picture and one line per option. Each tilt has its own cycle; the lens angle follows from them. The presets all store their one Cycle in `cycleDeg` (Partial reveal's slow cycle is computed); only Custom reads `cycleXDeg`. Switching effect (`src/lib/switchEffect.ts`) keeps flat, band, wobble and directions, carries the fastest playing cycle into a preset (back to the default if it's over 180°), and starts Custom from exactly what the current effect gives. No preset numbers. Hidden frames are an outcome shown with an eye-off icon and ↕/↔, never a setting. Lenticular only, no microlens arrays. The Lens effect's tilt map is only a picture (it doesn't tilt banknotes): a click swaps it for the print and back (no toggle; the hover tooltip says so). The print (`src/lib/print.ts`, `src/editor/PrintView.tsx`) is the selected banknote's thread, magnified, with its real frames tiled as on the banknote and cut into strips under the ridges: strips at the ridge angle, each frame's strip as wide as its length, the frame seen flat under each ridge's middle, drawn the same way round as the tilt map. The strips seen at the current tilt stay lit. Cycle alone never changes it. Ridges (shown only with the print) sets how many ridges it draws across the thread; it and the view are remembered per browser (`src/lib/printView.ts`), not saved in projects. Only the lens lab's ridge maths came over, none of its pitch numbers or print checks.
- **Thread pattern** (`src/lib/pattern.ts`, `ThreadPattern` on `Note.pattern`): frames are full-thread artwork and sections are masks over them. Sections sit in one repeat (1 to 250 mm, 4 by default) that tiles the thread; along is mm from the repeat's start, across a share of the thread's width. Editing snaps to 0.5 mm along and twelfths across, and sections never overlap: drawing cuts back, moving slides until blocked, and edges on one seam move together. Mixed angles is off by default: off, every section plays the banknote's lens (a section keeps its own for when it's switched back on); on, each plays its own, and fields it leaves out take the defaults, never the banknote's. Every section's print has one strip per banknote frame at that frame's length, so flat and the cycle mean the same everywhere; a section's track picks the frame each strip shows (by frame id, a shorter story padded). A banknote without a pattern is one section over the whole thread and is drawn by exactly the old path (tested against the old renderer). Presets: Single lens, Split band, Alternating (segments), Chevron lock; they keep the banknote's flat, Cycle and directions. The rules (`src/lib/patternRules.ts`) only ever warn: every window shows each tilt wherever the print lands, one rest frame, frames only some sections show under ridges within 10° of their tilt's axis (mirrored pairs fine), one strip count (only strips set for another number of frames, as after adding or deleting one; a story that repeats frames is fine), minimum 1 mm by 1 mm less a 0.2 mm dead zone where angles meet, at most 3 ridge angles, no gaps. The sizes are placeholders until Oberthur confirms them. The print isn't registered to the banknote: the offset is a preview only (`src/lib/patternOffset.ts`), remembered per browser by banknote, never saved or undone, shown only when some section is shorter than the repeat, followed by the canvas and export; the thread editor shows the repeat from its start. With Mixed angles, playback sweeps each tilt at its fastest section's cycle (both tilts when both play and there are no moves), and the timeline follows the section selected in the thread editor, else the first. The print cuts each section at its own ridge angle with one ridge width, over two repeats where it can (at most three thread widths long); gaps print nothing.
- **Timeline:** each frame has a relative `length`, and its share of the total is its share of the cycle. Cycle (`tilt.cycleDeg`) is per banknote, with the lens. `tilt.transition` (Fade), speed, curve, hold at ends and the moves list are project-wide. Fade and motion controls live in the Playback settings popover; the default is 0.75× speed (Keller, 3 November: 1× felt fast; saved projects keep their speed, and saves from before speed play at 1×), Smooth curve, no hold. They are stored on each note but always edited for all notes together, and must never resize the timeline. Past one cycle the frames loop. The timeline shows one cycle with no angle ruler.
- **Frames' artwork** (`src/lib/artwork.ts`, Keller, 3 November): a frame holds nothing (the thread's background shows), one colour over the whole thread, or one image (`Frame.kind` 'none' | 'color' | 'image'; no stacking). The thread's repeat (`ThreadPattern.repeatMm`) is the one tile for the sections and every frame's artwork: an image sits once per repeat where its place puts it (`ImagePlace`: along in mm from the repeat's start, across and size as shares of the thickness, so it keeps its place on a thicker thread; absent, it fits the repeat and the thread, centred), so its copies fall one repeat apart, and one that runs past the repeat's end carries on into the next (copies are never cut at seams). There is no Image gap. Images always stay upright, even on horizontal threads. The print's offset moves the artwork with the sections. A thread nobody has drawn sections on takes its repeat from its first image when it gets one (`patternForFrames`), so it repeats back to back. Frames record their image's proportions (`aspect`) when it is added; banknotes from before are read once when their project opens (`useSettleArtwork` → `settleArtwork`, no undo step): an untouched thread takes its repeat from its first image plus its old gap (`thread.imageGapMm`, then dropped), its images at the repeat's start and as thick as the thread, so it looks as it did (other images of other proportions keep that repeat); one with sections keeps its repeat, its images fitted. NoteView, the thread editor, the print preview and export all lay images out with `imageBox` and `copyStarts`. Separate from the paper bridges between windows.
- **Watermark:** at most one per banknote, a sibling of the thread (`note.watermark`, `src/lib/watermark.ts`), added from the + on the banknote's row; Duplicate keeps it. One image, read only by brightness, since a watermark is paper thickness and has no colour, and it only ever gets lighter, since it is light coming through thinner paper (Keller's rules). By default the image's light parts are the thinner paper (on transparency, as far as they are light; on an opaque background, as far as they are lighter than it), so it glows where the image is light, as a photo of a watermark held to the light does; Invert (a switch under Replace, any image; `watermark.invert`, saved only when on) makes the dark parts thinner instead, so a black logo glows. Keller chose this way round on 2 November (the first lighter-only build had them the other way). The background (its edge pixels, or transparency) and whatever lies the other side of it stay plain paper (`thinness` in `src/lib/relief.ts`). Levels then shape how thin that reading makes the paper (Keller asked on 2 November to control how an imported image comes out; built 3 November), three handles as in Photoshop's Levels on the slider under Auto levels: where the watermark starts (black; anything fainter stays plain paper), midtones (grey, a gamma that keeps its place between the ends as they move) and where it reaches the thinnest (white); plain paper always stays plain (`levelsCurve`). Auto, the default (no `watermark.levels`), fits them to each image as it is read (`autoLevels`): the start just above the background's speckle (4× the spread of its edge pixels, so JPEG noise stays plain paper; 0 on transparency) and the thinnest where all but 0.5% of the image reaches, so a faint scan comes up, gamma 1. Moving a handle saves `watermark.levels` and turns Auto off; switching Auto levels off keeps Auto's levels to set by hand, on again drops them. A new image, or removing it, starts on Auto again. On a black-on-white JPEG left the default way round, its compression ringing can still show faintly round the logo; Invert, which is the right reading for it, comes out clean. It is drawn as one layer colour-dodged over the design and under the thread, up to `THINNEST_GAIN` (2×) the light for the thinnest (`lightPixels`): it brightens the design in proportion, so it shows in the banknote's own colours, plain paper is unchanged and dark print stays dark, as ink blocks light. Its opacity is how much of that light comes through, so the reveal is more light, not an image fading in. On very light paper the screen has little room above the paper colour, so detail inside the glow can merge into white; only dimming the banknote when lit would fix that, which Keller ruled out. Darker, thicker parts (multiply), Hard light, Blend modes and an SVG Fill colour were all tried and removed: paper can't be coloured, and darkening reads as print. The thumbnail beside Replace shows the image in greyscale. Placed by its top-left corner in mm, its height following the image (X, Y and Width typed in the panel are kept exactly, in any unit; drags, nudges and a new watermark snap to 0.5 mm); Depth (0 to 100%) sets how strongly it shows at its clearest, tilted or held to the light. On the canvas it handles like the thread, as Keller asked: a press on it, faint or clear, picks it and a drag moves it (0.5 mm steps, once past 3 px so a click doesn't nudge it), so dragging there moves the watermark instead of tilting the banknote; with Depth 0, or in thumbnails, it takes no press. Placing works like windows, with no mode: picking the Watermark layer, pressing the watermark on the canvas, adding it or uploading its image shows the banknote flat with the watermark clear and its box to drag (styled like the window editor: solid fuchsia border with a ring; corners resize with the proportions kept, 0.5 mm steps, arrow keys nudge); a click elsewhere on the banknote, the empty canvas, Escape or another layer ends it, and Delete removes the watermark. Placing pauses playback and hides the tilt pad. Reliefs are worked out in steps (`src/lib/relief.ts`) so a drag on the levels stays live: each image's pixels once (at most 1024 px), then a reading per Invert (its thinness and Auto's levels, the last one showing while the next is worked out), then a light layer per levels drawn through a 256-entry table (`lightPixels`), a few of each kept. NoteView draws that layer on a canvas at the size it shows at (`reliefPixels`), scaled down smoothly so fine detail doesn't turn to grain, and export draws the same layer the same way.
- **Light:** how clearly the watermark shows (`src/lib/light.ts`). Flat in reflected light it is only a hint (`WATERMARK_FAINT`, 5% of its depth); tilting either way brings it out with no light needed, all of its depth (`WATERMARK_TILTED`) from `WATERMARK_TILT_DEG` (30°) on; held to the light it is clear even flat, which is what the light is for. Keller set this on 3 November: 30% flat was far too visible (a dollar's watermark can't be seen flat in normal light), then 2% flat with tilting held to 10% made it almost impossible to see tilted. Nothing else changes in the light: Keller was explicit that the design and the thread must look the same (no grey or monochrome filter, no dark thread, no darkened canvas). The lamp on the tilt pad, or a tap of L, holds every banknote up to the light until switched off; holding L peeks at the other light while it is down. The light fades in and out over `LIGHT_RAMP_SECONDS`. The live light is preview state (`useTilt`), not saved. Playback has a ☀ Hold to light move: flat, the light fades in, holds for its seconds and fades out; recordings keep the light too, and the pad draws the stretches played up to the light bold (a ring round flat for Hold to light). No amber anywhere for light: the app uses amber for ↔ and sky for ↕. Export matches the canvas: the watermark follows each frame's tilt and light, and the lamp left on makes it clear for the whole video.
- **Threads:** they can run vertically or horizontally, with windows switched on or off (off = continuous). Windows are individual start/end sections, listed in the panel and edited directly on the canvas, with no edit mode: selecting a window (panel row, canvas, switching windows on, or +) starts editing, and clicking elsewhere on the banknote, the empty canvas or Escape ends it: draw, move, resize, or delete, snapping to 0.5 mm. Start/End fields provide precise adjustment. Editing pauses playback and shows the banknote flat with hidden artwork faintly visible. On the canvas, dragging a thread moves it across the banknote (X for vertical, Y for horizontal, 0.5 mm steps), and clicking a window selects it for editing. Legacy repeating patterns migrate to sections. There is no white surround.

## Data

- Everything is stored in the browser's IndexedDB (`src/lib/db.ts`), images as blobs, and nothing goes to a server. Projects therefore live in the browser they were made in. Use the Demo button on the project list to get sample content anywhere. The demo is built in code (`src/lib/demo.ts`; its artwork, the printed faces, bird portrait, flapping bird, star and bird's head, is drawn on a canvas in `src/lib/demoArt.ts` and stored under fixed ids, once a session), so it changes only with the app; the shared template in Supabase (`supabase/demo/`) is no longer read. It opens playing its playlist (only a demo with one does), and leaving it stops playback and goes back to flat. Keep Mixed angles (several sections with their own angles) out of the demo until Keller knows it can be printed; its watermark sits in almost white paper with a slight green tint, and its playlist has no Hold to light (Keller, 3 November). Tests can't draw on a canvas, so they mock `createDemoProject` with a plain banknote. When a feature lands, consider showing it in the demo.
- When you change a saved shape, add a migration in `migrateProject` (`src/lib/notes.ts`) so existing projects keep working. An open tab can still hold the old shape in memory until it reloads.
- Image hooks that read a module-level cache (`useImageUrl`, `useRelief`, NoteView's `useImageAspect`) work out the value while rendering and, when it was missing, re-check in their effect: another view can fill the cache between this one's render and its effect, and the React Compiler won't recompute it without a state change.
- Every image a banknote uses must be listed by `projectImageIds` (`src/cloud/repository.ts`), or it isn't uploaded on save or copied from the demo, and by `noteImageIds` and `copyNote` (`src/lib/store.ts`), so Duplicate gives the copy its own. A new image field goes in all three.
